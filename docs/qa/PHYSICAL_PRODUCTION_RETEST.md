## AudioBook Physical Evidence

### Remediation

Physical TTS generation initially failed before its backend request. The root
cause was a runtime covariance mismatch: normalized chapter literals were
created as `Map<String, Object>` while `firstWhere` required
`Map<String, dynamic>`. The service now emits an explicitly typed map, derives
a stable restored AudioBook ID, and returns safe failure markers that never
persist. A regression test exercises the restored chapter runtime type.

The initial non-audible report exposed two product-state defects rather than a
hardware route failure. Restored books could select a later chapter without an
`audio_url` and silently advance a simulated player, while replaying a completed
MP3 with the same URL did not seek back to zero. The release remediation now
keeps chapters without MP3 in a truthful `Audio pendiente` state, disables
inapplicable player controls, guides the user to generate audio, and seeks a
completed real track to the beginning before replay. The targeted regression
suite covers both the pending-audio UX and completed-track restart decision.
