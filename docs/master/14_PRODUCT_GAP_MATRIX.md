# 14 — Product Gap Matrix

| Target area | Current state | Gap | Priority |
|---|---|---|---|
| Inicio | Simplified visually in Phase 1 | Upload UX regression; no controller | Critical |
| Biblioteca | Powerful but dense | Needs v2 IA library model and clean tabs | High |
| Aprendizaje | Student Dashboard overloaded | Needs simple student path | High |
| Teacher Studio | Features exist but no hub | Build hub and guard | High |
| Cuenta | Settings/plans split | Merge plan, usage, accessibility, language | Medium |
| Admin Console | Routes exist | Must be hidden + guarded | Critical |
| Role/Plan | Local plan driven | Need backend authority | Critical |
| Mobile Android | scaffold exists | API URL/file/audio/download QA | High |
| Web | works locally | deployment env/CORS/secret hardening | High |
| QA | almost absent | smoke + integration matrix | Critical |

## Top product gaps

1. Upload must feel instant and explain progress.
2. User identity, role and plan must be deterministic.
3. Main navigation must remain simple.
4. Biblioteca must become the trusted source of documents/results.
5. Teacher Studio must be separated from student learning.
6. Experimental enterprise features must not leak into v1.
